# «Ястреб» — дизайн MVP

## Уточнения реализации, утверждённые последующими сообщениями

Добавлены два режима: быстрый Top-3 и подробный Top-8. История теперь сохраняется между сессиями отдельно для каждого пользователя в SQLite.
Для первого рабочего запуска принят локальный вход по корпоративной почте и паролю; неподтверждённые заголовки прокси не используются для авторизации. Интеграция SSO/AD остаётся отдельным этапом.
Эти уточнения заменяют соответствующие исходные положения ниже. Изменение пользователей выполняется серверным администратором через CLI.

## Цель

Создать локальную RAG-систему для семантического поиска и формирования ответов по PDF-документам в закрытом корпоративном контуре без внешних API и сетевого доступа к Интернету.

## Пользовательский сценарий

Пользователь входит по корпоративной учётной записи, видит историю собственных запросов, задаёт вопрос и получает ответ с раскрываемыми источниками: имя файла, номер страницы и точная цитата. Библиотека документов изменяется только пользователями с правом `manage_library`; управление открывается через шестерёнку внизу боковой панели, вкладка «Внести изменения».

## Роли и доступ

MVP поддерживает три роли:

- `admin` — управление пользователями и библиотекой;
- `branch_head` — добавление PDF и запуск переиндексации;
- `worker` — поиск и просмотр ответов/источников без изменения библиотеки.

Сопоставление корпоративной почты с ролью хранится локально в конфигурации доступа. В сетевом режиме имя пользователя берётся из доверенного заголовка reverse proxy (`REMOTE_USER` или `X-Forwarded-User`); прямой доступ к приложению без прокси должен быть отключаемым. Для локальной разработки допускается явный demo-пользователь, но он не используется в production.

Проверка прав выполняется на серверной стороне перед каждой операцией загрузки и переиндексации. Скрытие вкладки в UI не считается защитой.

## Архитектура

1. Streamlit отвечает за чат, историю запросов, боковую панель и ролевое отображение.
2. `PdfIndexer` читает PDF с сохранением `source`, `page` и исходного текста страницы, затем режет документы на чанки размером 1000 символов с перекрытием 200.
3. `VectorStore` строит локальные эмбеддинги через `sentence-transformers` и сохраняет их в ChromaDB на диске.
4. `Retriever` запрашивает Top-3 чанка по смысловому сходству.
5. `RagService` передаёт только найденный контекст в Ollama с жёстким промптом отказа при отсутствии ответа.
6. Ответ содержит структурированные источники, а UI показывает их через `st.expander`.

Имена файлов и каталоги настраиваются через `.env`/локальный конфиг: `data/documents`, `data/chroma`, `data/manifest.json`, модель эмбеддингов, Ollama-модель и порог релевантности.

## Обработка документов

Загрузка разрешена только после установки пользовательского флажка подтверждения. Файл принимается только если расширение `.pdf`, размер не превышает настроенный лимит, а SHA-256 ещё не присутствует в манифесте. Переиндексация строится в новой временной коллекции и заменяет рабочую коллекцию только после успешного завершения; частичная индексация не должна становиться активной.

Если PDF не содержит извлекаемого текста, UI сообщает, что для MVP требуется текстовый PDF и OCR не включён. Это явное ограничение, а не тихий пустой результат.

## RAG и отказоустойчивость

Системный промпт требует использовать только контекст, цитировать только предоставленный текст и отвечать «В предоставленных документах ответ не найден», если контекста недостаточно. При пустой базе, недоступной ChromaDB, недоступном Ollama или отсутствии релевантных чанков UI показывает понятную ошибку/штатный отказ без выдуманных источников.

Для каждого ответа сохраняются только история текущей сессии и метаданные источников; содержимое документов не отправляется во внешние сервисы.

## Интерфейс

- слева история запросов и кнопка «Новый диалог»;
- внизу панели имя, корпоративная почта/роль и шестерёнка;
- настройки раскрываются вверх внутри боковой панели;
- вкладки настроек: «Внешний вид», «Внести изменения», «Профиль»;
- «Внести изменения» отображается только при наличии права или показывает отказ в доступе по выбранной политике;
- основной экран — чат с историей сообщений и источниками под каждым ответом;
- UI не обещает сетевой статус как гарантию безопасности: статус означает только состояние локальных компонентов.

## Что сознательно не входит в MVP

- полноценный LDAP/Active Directory-коннектор;
- OCR сканированных документов;
- распределённая ChromaDB и отказоустойчивый кластер;
- тонкая настройка прав до уровня отдельного документа;
- аудит в отдельную SIEM-систему;
- дообучение LLM.

Для production эти направления должны быть отдельными этапами.

## Приёмка

Система запускается без Интернет-соединения при заранее установленных зависимостях, индексирует тестовые PDF, возвращает Top-3 источника с файлами и страницами, отказывает при отсутствии ответа в контексте, не разрешает загрузку `worker`, и не активирует частично построенную коллекцию после ошибки индексации.
